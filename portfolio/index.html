Uncertainty changes the shape of a season.

The correlated model samples each team's latent strength once per rollout, then allows it to drift. A team that is stronger than its estimated mean tends to outperform across several games together. The fixed-strength model removes that shared uncertainty.

Compare the widths and tails, not just expected wins. These modes also differ in marginal probabilities and drift; this comparison does not isolate correlation alone.

What this supports

In this archived cohort, accounting for shared strength uncertainty produces wider ranges with coverage closer to the nominal target. Expected-win error is similar between modes.

This is evidence about this simulator and sample. It does not establish betting edge, universal calibration, or a statistically significant advantage.

What needs caution

Coverage includes a ±0.5-win boundary tolerance. Team outcomes within a season are dependent, and the five seasons are a small evaluation cohort.

Schedules and membership were reconstructed retrospectively. Exact provider publication times were not archived. Full limitations are part of the exhibit.

From game results
to correlated futures.

The exhibit exposes one quantitative mechanism from the broader SportsWorld engine: a latent-strength state-space model connected to a full-season simulator.

  1. Archived resultsESPN game records and retrospective schedule membership
  2. Latent strengthKalman posterior mean and variance for every team
  3. Season rolloutsShared strength draws, Gaussian margins and time drift
  4. DistributionsFinal wins and approximate playoff qualification

The generative model

θᵢ ∼ Normal(μᵢ, vᵢ)
θᵢ(t + Δt) = θᵢ(t) + Normal(0, qΔt)
margin = home advantage + θₕ − θₐ + ε
ε ∼ Normal(0, observation variance)

The fixed-strength mode holds θ at the posterior mean. Both modes use Gaussian margins here. The separate logistic game classifier in the full engine is not used by this exhibit.

    The public exhibit is static. Its data, saved interventions and evaluation rows ship with the website. The full Python engine and original live interfaces remain in the repository.

    Run the exhibit with no API keys

    git clone https://github.com/rajdeeepm/SportsWorld.git
cd SportsWorld
python -m http.server 8080 --directory portfolio

    Open http://localhost:8080. There is no database, model server, login, paid provider or live sports feed required for this public mode.

    Regenerate the saved simulations

    python -m venv .venv
source .venv/bin/activate
pip install -e backend
python scripts/export_portfolio.py
node scripts/verify_portfolio.mjs

    The exporter reads the bundled historical inputs and runs the existing simulator with seed 17 and 10,000 draws per branch. It writes the browser snapshot. It makes no provider calls. The input hash makes changes to the underlying evidence inspectable.

    Inspect the original live system

    The hackathon application includes additional leagues, game views, context ingestion and optional agent/voice integrations. Those capabilities require their original runtime and data setup; they are demonstrated in the recording rather than presented as active services here.
